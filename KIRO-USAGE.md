## What Kiro's workflow actually did here

This project was built spec-first, the way Kiro works:

1. **Specs first** — before any game code, four specs were written in
   `.kiro/specs/` (`flash-graveyard-hub`, `snake`, `breakout`, `memory`),
   each with `requirements.md` (user stories + acceptance criteria),
   `design.md` (architecture, logic API, data model) and `tasks.md`
   (implementation checklist). The code was then implemented against
   those specs, and task boxes were checked only after their tests
   passed.
2. **Steering** — `.kiro/steering/product.md`, `tech.md` and
   `structure.md` record the project's non-negotiables (static-only,
   no paid services, no third-party assets, pure logic separated from
   UI, tests before commit) so any Kiro surface (IDE, CLI, Web, Crew)
   follows the same conventions when it works on the repo.
3. **Hooks** — `.kiro/hooks/` holds two v1-format hooks (per
   https://kiro.dev/docs/hooks/):
   - `test-on-save.json` (`PostFileSave` on `src/**/*.js` or
     `tests/**/*.js`) runs `npm test` whenever the agent saves a source
     or test file.
   - `verify-on-stop.json` (`Stop`) prompts the agent to run the full
     test suite and verify the spec task boxes are honest before ending
     a session.
4. **CLI** — Kiro CLI 3.4.0 was installed in the build VM and its
   version verified. The repo is ready to open in Kiro IDE/CLI/Web:
   `kiro-cli` in the project root picks up `.kiro/` automatically.

## What Kiro did NOT do (yet)

- No Kiro agent session was authenticated in this build, so no code was
  generated by a logged-in Kiro agent here. The specs, steering, hooks
  and code were authored in this session following Kiro's spec-driven
  workflow; the user will run the authenticated Kiro workflow
  (login → specs → tasks) for the remaining polish and the demo.
- The `.kiro` directory is committed at the repo root and is **not** in
  `.gitignore`, per the Kiroween rules.

## For the user: Kiro login steps

1. Install the CLI (already done in this VM; on your own machine):
   `curl -fsSL https://cli.kiro.dev/install | bash`
2. `kiro-cli login --license free` — pick **AWS Builder ID** (free,
   no AWS account or credit card needed; an email address is enough).
   A browser window opens; sign in / create the Builder ID there.
3. `kiro-cli` inside this repo to start an agent session. It reads
   `.kiro/specs`, `.kiro/steering` and `.kiro/hooks` automatically.
4. Optional: request the 4,000 Kiroween credits via the Credit Request
   Form linked in the hackathon rules — deadline **Dec 1, 2026, 12:00pm
   PT**, and the form needs your Kiro user ID.
